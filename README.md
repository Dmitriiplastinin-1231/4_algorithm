# Lab 4: Optimization Algorithms

This project provides a Tkinter GUI for two tasks:

1. **Hamiltonian path in a grid** — find all paths from a start cell to a finish cell that visit each free cell exactly once.
2. **15-puzzle** — solve the puzzle to the goal state in the minimum number of moves.

## Requirements

- Python 3 with Tkinter (usually included in standard Python distributions).

## Run

```bash
python main.py
```

## Notes

- The Hamiltonian path search can be extremely expensive on large grids. Start with smaller sizes or add blocked cells to reduce runtime.
- For the 15-puzzle, random positions are generated by making random valid moves from the goal to ensure solvability.
- The puzzle board size can be adjusted in the UI before solving.

## Research scripts (CSV output)

Two CLI scripts are included to run parameter studies and export metrics to CSV.

### 1) Hamiltonian path studies

```bash
# Warnsdorff randomness (alpha = 0, 0.1, 0.5, 1, 2)
python research_hamilton.py warnsdorff --rows 4 --cols 4 --start 0,0 --finish 3,3 --trials 3 --output warnsdorff.csv

# Connectivity pruning frequency (every step, every 2, every 5, danger-only)
python research_hamilton.py connectivity --rows 4 --cols 4 --start 0,0 --finish 3,3 --trials 3 --output connectivity.csv

# Backjumping depth variants
python research_hamilton.py backjumping --rows 4 --cols 4 --start 0,0 --finish 3,3 --trials 3 --output backjumping.csv

# Grid size impact (4x4, 5x5, 6x6, 7x7)
python research_hamilton.py grid_size --trials 3 --output grid_size.csv

# Start/finish impact on 4x4
python research_hamilton.py start_finish --trials 3 --output start_finish.csv
```

Main exported metrics:
- elapsed, recursive_calls, backtracks, dead_ends, solutions
- pruned_states (for connectivity studies)
- jumps, depth_reduction (for backjumping studies)
- max_depth, status

### 2) 15-puzzle studies

```bash
# Weighted Manhattan: f = g + w*h, w = 0.5, 1, 1.5, 2, 3
python research_puzzle.py weighted_manhattan --size 4 --scramble-depth 20 --trials 5 --output weighted_manhattan.csv

# Linear conflict: h = Manhattan + beta*conflicts, beta = 1,2,3,4
python research_puzzle.py linear_conflict --size 4 --scramble-depth 20 --trials 5 --output linear_conflict.csv

# Scramble depth impact: 5, 10, 20, 50 (IDA* and BFS)
python research_puzzle.py scramble_depth --size 4 --trials 5 --output scramble_depth.csv
```

Main exported metrics:
- elapsed, expanded, solution_length, status
- optimal_length and optimality (weighted Manhattan study)
- peak_open_size for BFS (scramble depth study)

Both scripts support `--time-limit` and `--node-limit` to cap expensive runs.

## Best-variant algorithm comparison

To compare the best variants found in the studies and save separate summary tables for both tasks:

```bash
python compare_algorithms.py --output-dir comparison_outputs
```

By default the script:
- compares task 1 algorithms on a 4x4 grid with start `(0,0)` and finish `(3,3)`
- uses the best study settings: Warnsdorff `alpha=0.1`, connectivity pruning `policy=1`, backjumping `mode=max_conflict`
- compares task 2 algorithms on a 4x4 puzzle with scramble depth `20`
- uses the best study settings: IDA* with `w=1.0` and linear conflict with `beta=2`

Generated files:
- `comparison_outputs/task1_algorithm_comparison.csv`
- `comparison_outputs/task2_algorithm_comparison.csv`
